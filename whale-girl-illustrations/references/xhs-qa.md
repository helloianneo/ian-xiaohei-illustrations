# 小红书图文 QA 清单

生成或交付小红书首图、单张配图和轮播图时使用。它补充 `qa-checklist.md`，不是替代角色和风格检查。

## 页面规格

- [ ] 每张都是 3:4 竖版，建议 1080×1440；没有误用 2:3、1:1 或横图。
- [ ] 标题、项目名、关键数字和主要截图位于安全区域，没有贴边或被底部平台界面遮住。
- [ ] 首图缩小到手机缩略图后，仍能读出主题和结果钩子。
- [ ] 轮播页顺序明确，每页可以脱离上下页理解自己的核心意思。

## 内容职责

- [ ] 首图只负责钩子、项目名和一个事实/结果，没有塞完整介绍。
- [ ] 每个内容页只有一个主标题和一个主任务，没有把多个信息点挤成小字。
- [ ] 亮点页最多保留 2–3 个最有差异的功能；证据页优先呈现截图、数据或前后变化。
- [ ] 整组只提炼正文约 20%–30% 的核心信息，没有把全文逐页搬运。
- [ ] 结尾页的 CTA、关注话术或互动问题来自用户或内容依据，没有凭空营销。

## 角色和视觉占比

- [ ] 首图鲸鱼娘通常占 20%–30%，没有压过标题。
- [ ] 信息页鲸鱼娘通常占 8%–18%，截图、数字和正文仍是主角。
- [ ] 默认每页一个鲸鱼娘主体；小鲸鱼 0–1 个，且有表达作用。
- [ ] 没有把鲸鱼印到杯子、电脑、围裙、Logo、边框和所有道具上。
- [ ] 整组角色仍像同一个 IP，发色、女仆装、发箍、蝴蝶结、鲸鱼耳朵、尾巴和脸部完成度一致。

## 排版和事实

- [ ] 中文、项目名、GitHub Stars、版本号、代码和数字已经后期排版或逐字核对。
- [ ] 没有使用 AI 生成的假 UI、假 Logo 或未经来源确认的动态数据冒充事实。
- [ ] 标题层级、正文层级、数据层级和 CTA 层级在整组中一致。
- [ ] 正文不是密集小字墙；移动端阅读时不需要放大才能理解。
- [ ] 页面不是等宽卡片墙、九宫格、信息仪表盘或长海报切片。

## 系列统一

- [ ] 每页使用同一组背景色、纸感、深蓝边框、淡蓝标题底刷和主色规则。
- [ ] 每页可以有不同动作和构图，但没有复制同一个站姿或把角色机械贴到角落。
- [ ] 首图、内容页和结尾页的差异来自页面职责，不是来自随意更换画风。
- [ ] 没有明显深黄、灰色、脏旧纸、塑料 3D、过度光泽或人物全身草稿化。

## 交付

- [ ] 文件按 `01-cover`、`02-problem` 等页面职责命名，页数与实际内容一致。
- [ ] 单图明确标记为 cover 或 single-card；轮播没有缺页、空页或重复页。
- [ ] 没有 `by ian and 小黑`、签名、水印、二维码或未经要求的品牌角标。
- [ ] 没有自动发布；用户在外部发布前已经看过最终预览。

## 失败时的修复顺序

1. 先修比例和安全区。
2. 再缩小鲸鱼娘和道具，恢复标题、正文和截图的阅读空间。
3. 再删重复信息，保留用户指定的事实字段。
4. 再用后期排版修正中文、数字和数据。
5. 最后调整边框、气泡和小鲸鱼装饰，恢复灵性但不增加噪音。
