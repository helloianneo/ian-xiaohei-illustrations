# 小红书图文工作流

## 适用范围

用户提到小红书、笔记、封面、首图、轮播、多图或配图时，使用这份规则。它负责内容结构和移动端阅读；`style-dna.md`、`whale-girl-ip.md` 负责鲸鱼娘的视觉身份。

## 两层工作方式

### 视觉 IP 层

- 必须使用 `assets/whale-girl-reference/` 中的实际图片作为角色参考。
- 保持蓝发、深蓝白色女仆装、白色蕾丝发箍、侧边蓝色蝴蝶结、鲸鱼鳍耳朵、蓝色尾巴和精致 Q 版脸部。
- 保持一组图片中的角色身份一致，但可以改变表情、动作、视线、裁切和出场比例。
- `content-card-spirit.png` 只校准边框、纸感、底刷、气泡和灵性，不复制它的具体文案或布局。

### 小红书内容层

- 默认 3:4，1080×1440。
- 首图负责点击钩子；内容页负责解释、证据和判断；结尾页负责总结或用户提供的 CTA。
- 文字和事实证据是页面的主内容，鲸鱼娘是视觉锚点和叙事回应。
- 精确中文、项目名、数字、星数、代码和步骤必须后期排版或逐字复核。

## 单图还是轮播

按以下顺序判断：

1. 用户明确只要一张图，生成首图或单张内容卡片。
2. 用户只给一个观点、一个结果或一个动作，生成首图或正文场景隐喻。
3. 用户要求项目介绍、特色亮点、数据、步骤、体验或“后边包括……”，默认规划 4–6 张轮播。
4. 只有主题互相独立且单张会导致文字不可读时才增加页数；不能为了填满 6 张重复信息。

不把一张长海报切成多页。每一页都必须有自己的标题、信息作用和独立构图。

## 轮播分页模板

默认从下列页面职责中选 4–6 个：

1. **封面**：短痛点或结果钩子 + 项目名/一个事实。
2. **问题**：用户正在遇到的具体场景，文字短、画面有动作。
3. **亮点**：2–3 个最有差异的功能或价值，每个用短句，不写完整说明书。
4. **证据**：项目截图、官方页面、Stars、前后变化或真实使用步骤，标明事实来源。
5. **判断**：适合谁、注意什么、作者体验或使用建议。
6. **总结**：一句结论、保存提示或用户提供的 CTA；没有依据时不要擅自营销。

对工具或 GitHub 项目推荐，优先使用“封面—问题—亮点—证据—判断”五页结构。若用户只需要一张图，则把亮点压缩成 2–4 个短信息区，不能照搬五页内容。

## 页面预算

### 首图

- 标题、项目名和一个结果是主阅读对象。
- 鲸鱼娘通常占 20%–30%，道具只表达标题关系。
- 只保留一个视觉动作，不放完整功能清单。

### 内容页

- 标题 + 2–4 条短句或一个截图/数据证据。
- 鲸鱼娘通常占 8%–18%；信息密集页可以只出现半身、脸、手或尾巴。
- 截图、Logo 和真实数据不能被角色或装饰遮住。

### 结尾页

- 以结论、适用人群、注意事项或用户提供的 CTA 为主。
- 不为了“像小红书”凭空添加关注、点赞、评论和购买话术。

## 系列风格锁

生成第一张之前先确定，并在整组中复用：

```text
画布：1080×1440，3:4
背景：接近白色的非常浅暖白纸感
边框：深蓝轻手绘边框
标题：深蓝文字 + 淡蓝底刷
强调：蓝色为状态，红橙只强调关键结论
角色：同一组鲸鱼娘参考图，精致 Q 版，手绘感在辅助元素
装饰：气泡、箭头、下划线和小鲸鱼涂鸦少量使用
文字：标题/副标题/正文/数据/CTA 层级固定
```

允许每页改变姿势和构图，不允许改变角色发色、服装、尾巴、脸部完成度和整体配色。

## 素材和事实

- 用户提供的截图、照片和参考图优先使用；它们可以作为内容证据，但不能替换鲸鱼娘身份参考。
- GitHub Stars、Forks、版本号和项目功能属于动态事实。生成前读取用户提供的链接或官方来源，记录取数时间；不凭旧记忆补全。
- 真实截图比 AI 绘制的“软件界面”更可信。若没有截图，使用干净的事实区或请用户提供，不伪造界面和数据。
- AI 生成的道具可以做隐喻，但不能冒充项目的真实 UI、Logo 或官方截图。

## 输出包

轮播交付至少包含：

```text
01-cover.png
02-problem.png
03-features.png
04-evidence.png
05-verdict.png
```

按实际页数命名，不能为了凑文件名生成空页。若只做一张，明确标记为 cover 或 single-card。生成前先给出页码、页面作用和精确文字草案，除非用户已经明确要求直接生成。

不要自动发布到小红书。发布属于独立的外部操作，必须由用户单独明确授权，并在发布前让用户看到最终预览。
