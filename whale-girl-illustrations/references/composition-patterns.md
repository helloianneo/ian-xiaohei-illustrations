# 竖版构图与隐喻模式

## 使用原则

每张图只选一种主结构，再根据正文重新发明物件和动作。结构是画面骨架，不要把结构名称写到图上，也不要把结构画成规整的 PPT 模块。

默认构图要让鲸鱼娘参与事件。她可以居中偏下、位于事件交汇处，或成为纵向动作的起点和结果；不要默认让角色站在左下角当比例尺。

## 可选结构

### 单一概念隐喻

用一个低科技物件承载抽象关系，例如潮汐桶、回声贝壳、浮桥、筛网、抽屉、闸门、打结的海草绳、漏水的水箱或奇怪的工作台。鲸鱼娘必须操作物件。

适合判断、阻力、闭环、沉淀、过载和承接。

### 事件前后

在同一张竖版图里用一个明显动作表达变化，例如上方混乱的潮流落入下方清晰的容器，中间由鲸鱼娘完成转折。不要画成左右两栏或两张卡片。

适合“从混乱到稳定”“从想法到成品”“从断点到承接”。

### 纵向路径

用一条弯曲、断开或被修补的路径从上到下推进。路径可以是水流、绳索、浮桥、纸带或贝壳轨道。最多保留 3 个可辨认节点，不做正式流程图。

适合输入、处理、结果和用户路径，但要让路径成为一个物件，而不是一串方框箭头。

### 角色状态

同一位鲸鱼娘在一个连续场景里经历两个状态，例如被潮水推着走到抓住锚点，或从一团线里捞出一个清晰结。不要复制多个相同人物做表情包排列。

适合痛点、焦虑、卡住、选择和反馈。

### 单一系统局部

只画一个小装置的关键部分，最多 3–5 个实体物件。鲸鱼娘在其中操作一个阀门、开关、筛网、连接点或记录口，其他模块留白或模糊处理。

适合 AI 工作流、内容系统、反馈回路和工具协作。

## 隐喻生成公式

先把抽象关系改成物理动作，再给动作找一个物件，最后让鲸鱼娘负责动作：

```text
抽象关系 → 物理动作 → 低科技物件 → 鲸鱼娘的具体动作 → 一个可见结果
```

例如：

```text
信息筛选 → 只让一条线通过 → 潮汐筛网 → 鲸鱼娘拉紧筛网边缘 → 清晰线落入盒中
```

## 避免 PPT 感

- 不用等宽卡片、规整网格、流程节点、仪表盘、标题栏和图例。
- 不让每个信息点都拥有一个图标和一段文字。
- 不用同样大小的气泡组成信息层级。
- 不用大量箭头解释每一步，优先用水流、绳索、缺口、重力、门和接触关系表达方向。
- 不为了“信息完整”牺牲人物动作和留白。

## 装饰预算

默认只从下面几类中选 2–4 类：

- 深蓝轻手绘边框
- 淡蓝标题底刷
- 一个小气泡
- 一到两个手绘箭头
- 少量纸张或 doodle 质感
- 一个具有表达作用的小鲸鱼

若装饰不能帮助理解主题，就删掉。鲸鱼图案不作为默认装饰预算。
