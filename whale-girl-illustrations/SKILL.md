# 鲸鱼娘手绘正文配图

## 核心定位

为中文文章、帖子、项目介绍、工具推荐、方法论和小红书内容生成 3:4 竖版手绘配图。支持两种明确分工的成品：少字、强标题、负责吸引点击的封面图；信息量较多、负责讲清内容的信息页。

用户明确说“小红书”“封面”“首图”或要求一组项目介绍图时，默认把封面作为独立第一页，后面再放信息页。用户只要求正文配图或单张信息图时，不额外增加封面。封面不承担项目介绍、功能、适合人群和 GitHub 数据等完整信息。

画面目标是“白纸上的手绘解释页”：可以有标题、分区、要点、数字、气泡和底部结论，但要像手绘内容页，不像商业 PPT、后台仪表盘或模板化卡片墙。

工作方式沿用小黑 Skill 的稳定骨架：一张图只保留一个主题和一个视觉锚点；鲸鱼娘做一件解释主题的事；每次根据当前文案重新发明画面，不复刻旧构图。

用户明确要求生成时，直接使用内置 `image_gen` 逐张生成，不先展开复杂的轮播规划、信息架构或后期排版流程。生成前仍要用一句话锁定标题利益点，并为信息页锁定一条从上到下或从左到右的阅读脊柱。

按任务需要读取：

- `references/whale-girl-ip.md`：鲸鱼娘、小鲸鱼的身份、动作和数量规则。

不需要读取或寻找外部布局示例。角色参考图只负责锁定鲸鱼娘身份：默认使用 `assets/whale-girl-reference/whale-girl-neutral.jpg`；只有需要笑脸或挥手动作时，才额外使用 `whale-girl-smile.jpg` 或 `whale-girl-wave.jpg`。

## 工作流

### 1. 消化文案并选择成品类型

先读用户给出的正文、链接、截图或文案，提炼：

- 这张图唯一的主主题。
- 鲸鱼娘可以参与的一个动作或视觉锚点。
- 必须保留的项目名、数字、结论和短句。
- 哪些内容留在正文，不塞进图片。

默认根据任务路由：

- 用户说“封面 / 首图 / 小红书系列”，或要求一组小红书项目介绍图时，先生成一张“封面图”。
- 项目介绍、工具推荐、功能说明、方法论和用户明确说“信息量多一点”时，使用“信息丰富单页”模式。
- 情绪、痛点、单个概念或用户明确说“少字/留白多”时，使用“简洁隐喻”模式。
- 用户明确要求多张，或文案有多个独立主题且单页无法清楚承载时，使用“信息丰富系列页”模式。

封面只提炼一个最值得点击的结论、痛点、结果或反差，通常只放一个主标题和可选的一句极短副标题。主标题优先写用户收益或内容钩子，项目名、Skill 名和仓库名降为小标签；不要把栏目名或产品类型当成最大标题，也不要把信息页缩小后当封面。

信息丰富不等于全文搬运。把相关内容组织成 3–5 个手绘信息区，每区只放一个小标题和 1–3 行短说明；保留更多有用信息，但不生成密集小字墙。

### 2. 选择一个结构

封面读取 `references/cover-mode.md`，只选择一个标题构图。信息页从 `references/composition-patterns.md` 选择一个结构，并先确定唯一阅读脊柱；可以有 3–5 个相关信息区，但它们必须沿同一方向排布并服务同一个主主题，不能散落在角色四周，也不能把多个海报拼成一张总海报。

### 3. 生成前写短策略

内部只写清楚：

```text
主题：
成品类型：封面图 / 简洁隐喻 / 信息丰富单页 / 信息丰富系列页
标题与副标题：
封面的一眼主语（封面时填写）：
3–5 个信息区及其短文案（信息页时填写）：
阅读脊柱与区块顺序（信息页时填写）：
视觉锚点：
鲸鱼娘正在做什么：
小鲸鱼正在做什么（可选）：
主要物件：
关键数字或结论：
底部收束句或 CTA（可选）：
```

### 4. 单张生图

封面按 `references/cover-mode.md` 生成；信息页按 `references/prompt-template.md` 生成。每张都是独立的严格 3:4 竖版图，系列模式逐页生成。必须把角色参考图作为 image reference 传给图像工具，不要只写“蓝色鲸鱼娘”而不传图。

### 5. 检查和迭代

生成后读取 `references/qa-checklist.md`。出现失败信号时，优先针对一个问题重生成或编辑：标题像印刷体就只修正标题字形，信息散乱就只收束阅读脊柱，文字太少就补信息区，角色太大就缩小主体；不要一次叠加所有元素。

## 不可违背的规则

- 默认严格 3:4 竖版，不接受默认 2:3。
- 封面必须独立生成：只保留一个主标题、可选的一句极短副标题或小标签，以及一个鲸鱼娘主视觉；不放 3–5 个信息区，不罗列功能、配置和 GitHub 数据。
- 封面主标题必须是第一视觉锚点。标题允许占据上方约 28%–40% 的画面，优先 1–2 行大字，只强调一个关键词；标题附近必须有明显留白。
- 封面主标题优先使用 6–12 个中文字表达用户收益、痛点、结果或反差；项目名、Skill 名、英文名和仓库名只能作为较小标签，不能成为最大的红色英文单词。
- 封面和信息页的文字都要像同一支粗头马克笔或毛毡笔手写：笔画略有粗细变化、基线轻微不齐、转折和收笔自然；禁止光滑几何黑体、标准无衬线印刷字和数字排版感。
- 一张图只保留一个主主题和一个视觉锚点；信息丰富模式允许 3–5 个相关信息区。
- 信息丰富单页默认包含：一个主标题、可选副标题、3–5 个信息区、10–18 个短文本单元，以及可选的数字/结论/CTA。正文仍需短行化，不复述全文。
- 信息页的主标题同样必须一眼先被看到：为标题保留独立的上方区域，主标题明显大于分区标题，正文和第一个信息框不得紧贴标题。可以把一个关键词改成红橙色、加淡蓝底刷或扩大字重，但不要同时使用多种强调。
- 信息页必须只有一条可追踪的阅读脊柱，默认从上到下；最多两列，区块共享清楚的左边线、编号轴或同一纸带。角色固定在一个动作区，不把文字散落到角色四周。只有真正的流程页才使用连续箭头。
- 用户明确要求多张时，每页仍是 3:4；每页只讲一个独立小主题，保持同一框线、背景、角色和配色，不把一页塞成缩小版目录。
- 鲸鱼娘必须参与视觉锚点或核心动作，不能只是站在信息区旁边或作为贴纸。
- 鲸鱼娘是精致 Q 版主体；手绘感主要来自线条、文字、框线、底纹、气泡、箭头和道具关系，不能把人物画成全身草稿。
- 小鲸鱼默认 0–1 个；只有主题确实需要群体、尺度、反馈、水流、陪伴或连续动作时才增加到 2–4 个，必要时再按画面需要增加。每只都要有动作、尺度或情绪作用，不能把鲸鱼印在每个物件上。
- 背景必须是接近白色的非常浅暖白；保留深蓝手绘外围框线、淡蓝文字底纹、少量气泡和红橙重点。
- 信息区可以使用手绘边框、底刷、编号、图标或气泡，但全页只选一种主要容器语言。区块可有大小差异，却必须沿同一阅读轴对齐；不做等宽等高的规整网格，也不做四处漂浮的撕纸拼贴。
- 标题可以清楚醒目，但不要让巨大标题吃掉画布上方大半空间；不要自动写“Workflow”“系统架构图”等结构名称。
- 用户提供的项目名、数字和结论必须尽量原样保留，不擅自发明数据、星数、版本或日期。
- 简洁模式通常 3–8 处短标注；信息丰富模式按信息区组织文本，允许明显多于 8 处，但每行都要短、可读、有层级。
- 禁止商业 PPT 风格、等宽卡片墙、九宫格、正式流程图、UI 截图、后台仪表盘、商业扁平插画、塑料 3D、强阴影、渐变、脏旧纸和科技感界面。
- 禁止完整文章、密集不可读的小字、每个信息点一个重复框、每个物件一个鲸鱼图案。
- 禁止 `by ian and 小黑`、签名、水印、二维码和未经要求的品牌角标。

## 交付判断

信息丰富模式的合格结果应像你愿意收藏的小红书手绘内容页：标题和层级清楚，读者能获得多条有用信息，鲸鱼娘仍然在做与主题有关的事，画面还有呼吸感。若第一眼像模板化 PPT、等宽卡片拼贴、密集说明书或角色贴纸，就不合格。
