# 鲸鱼娘小红书图文

## 定位

把中文内容变成适合小红书移动端阅读的 3:4 竖版首图、轮播图或单张内容卡。鲸鱼娘是固定视觉 IP 和情绪锚点，不是必须占据画面中心的大型立绘；她可以是事件的行动者、观察者、解释者或评论者。

这个 Skill 有四种模式，用户明确提到“小红书、笔记、封面、轮播、配图”时，优先进入前两种：

- **小红书首图模式**：适合笔记封面、项目推荐、工具种草和结果型标题。首图只承担点击钩子、一个事实或一个结果，不塞完整介绍。
- **小红书轮播模式**：适合“介绍 + 亮点 + 数据 + 使用建议”等需要连续阅读的笔记。默认规划 4–6 张，每张只讲一个核心意思，整组共享同一套角色、边框、颜色和文字层级。
- **单张内容卡片模式**：适合用户明确只要一张图，且要求保留一定文字量的项目介绍、特色、数据、体验和 CTA。
- **正文场景隐喻模式**：适合正文插图、一个判断、一个冲突或一个前后变化。用鲸鱼娘和一个物件完成核心动作，文字较少。

所有模式都必须严格输出 3:4 竖版，默认尺寸为 1080×1440。小红书轮播不是把一张长海报切开，而是多张独立、可单独阅读的页面。没有明确组图需求时仍然只做一张。

按当前任务需要读取，不要把无关参考全部塞入上下文：

- `references/whale-girl-ip.md`：实际角色参考图、身份锚点、表情和角色参与方式。
- `references/visual-distillation.md`：正文提炼、模式选择和单图/组图判断。
- `references/composition-patterns.md`：内容卡片构图和场景隐喻构图。
- `references/prompt-template.md`：带参考图的生图、精确文字和编辑模板。
- `references/qa-checklist.md`：比例、文字密度、角色大小、PPT 感和参考图一致性检查。
- `references/xhs-workflow.md`：小红书首图、轮播图、素材证据和系列统一规则；用户提到小红书时必须读取。
- `references/xhs-qa.md`：小红书移动端、封面缩略图、分页、文字排版和组图一致性检查；生成小红书图文时必须读取。

生成鲸鱼娘时必须使用 `assets/whale-girl-reference/` 中的实际图片作为角色参考，不得只依赖文字提示词。`assets/layout-reference/content-card-spirit.png` 只用于校准文字层级、留白、手绘边框和“灵性”，不要照抄其中的具体文案或构图。

## 工作流

### 1. 读取内容和用户要求

先读正文、链接、截图或用户给出的文案，区分：

- 必须原样保留的标题、数字、项目名和 GitHub 数据。
- 需要提炼的正文核心信息。
- 只适合留在正文、不应塞进图片的背景细节。

“只提炼正文约 20%–30%”是**语义选择预算**，不是“只能放 0–4 个标签”。内容卡片模式可以有标题、副标题、多个短段和 CTA，但不能复述全文。

如果用户给了 GitHub、产品页或项目链接，链接中的项目名、功能、星数和截图属于事实素材。需要实时数据时先读取来源，不凭记忆补数字；AI 生成的鲸鱼娘负责表达情绪，不能替代项目截图、Logo 或数据证据。

### 2. 选择模式

用户提到“小红书、笔记、封面、首图、轮播、多图、配图”时：

- 只要一张图，使用小红书首图模式或单张内容卡片模式。
- 需要介绍、亮点、数据、步骤或体验，使用小红书轮播模式，默认 4–6 张。
- 用户未指定页数时，先按内容量判断 4 张、5 张或 6 张；不要为了凑页数拆碎一个信息点。
- 用户明确要求“正文配图”“文章插图”且没有小红书语境，使用单张内容卡片或正文场景隐喻模式。

满足以下任一条件，优先使用单张内容卡片模式：

- 用户指定开头文案，并要求介绍、特色、星数、Fork、适合人群或体验。
- 用户明确说“要有一定文字量”“保留信息”“做成文章配图/内容卡”。
- 内容包含两个到四个可并列但需要阅读顺序的核心信息。

否则使用正文场景隐喻模式，保留一个核心判断、一个主要动作和一个可见结果。

小红书轮播的详细分页和版式预算见 `references/xhs-workflow.md`。不要把轮播每一页都做成同一种卡片，也不要把鲸鱼娘复制成每页同一个站姿。

### 3. 先写短策略，再生成

生成前先在内部写清楚：

```text
模式：内容卡片 / 场景隐喻
核心判断：
文字层级：
鲸鱼娘身份参考：neutral / smile / wave
鲸鱼娘在内容中的作用：
画面构图：
精确文字与后期排版计划：
小红书页码与页面作用：封面 / 问题 / 亮点 / 证据 / 总结（如适用）
系列风格锁：边框、底刷、颜色、角色比例、字体层级
```

内容卡片模式要先安排文字区域，再安排角色和道具。场景隐喻模式要先安排动作关系，再决定是否需要短标签。

小红书轮播模式要先写整组页面结构，再逐页生成。首图不复述正文；中间页各自承担一个信息点；最后一页只有在用户提供或内容确实支持时才加入 CTA。每页的角色、截图、道具都必须服务于该页核心意思。

### 4. 生成和文字处理

每张图单独调用图像生成工具，并将角色参考图作为图像参考传入。若用户给了精确中文、数字或 GitHub 星数，优先生成带干净留白的背景、角色和手绘结构，再通过后期排版放入准确文字；不要让模型自行发明数字、标题或项目名。

小红书图文必须把“图像生成”和“文字排版”分开：图像模型负责角色、背景、道具、边框和留白；精确中文、数字、项目名、星数、代码或步骤使用后期排版。若环境支持 HTML/CSS、Playwright 或其他确定性排版方式，优先使用；否则也要在交付前人工逐字复核，不接受乱码、错别字或随机数字。

### 5. 保存和复核

在 workspace 内工作时，把最终图保存到：

```text
assets/<article-slug>-illustrations/
```

不要覆盖已有资产。交付前读取 `references/qa-checklist.md`，至少检查比例、文字密度、角色大小、参考图身份、背景色、PPT 感、人物精致度和水印。

## 不可违背的底线

- 默认严格 3:4 竖版，不接受默认 2:3。
- 默认一张图；不要按信息点机械拆图。
- 用户明确要小红书轮播时，按页面职责拆图；默认 4–6 张，每张一条主线，不做长海报切片。
- 只选正文约 20%–30% 的核心信息，不搬运全文。
- 小红书首图和内容卡片可以有一定文字量；不要把小红书页面误判成 PPT，也不要为了反 PPT 删除用户明确要求的有效信息。
- 默认一张图一个鲸鱼娘主体。首图角色通常占 20%–30%，小红书内容页通常占 8%–18%，单张内容卡片通常占 15%–25%，正文场景隐喻模式通常占 35%–55%；都不能挤掉主要文字或动作。
- 小鲸鱼角色默认 0–1 个；少量鲸鱼涂鸦只有在能形成呼吸、反馈或叙事节奏时才可出现，不能把鲸鱼印到所有道具上。
- 人物必须使用实际参考图，保持蓝发、深蓝白色女仆装、白色蕾丝发箍、侧边蓝色蝴蝶结、鲸鱼鳍耳朵、蓝色鲸鱼尾巴和精致 Q 版脸部；可以变换表情、动作和视线。
- 精致 Q 版是人物主体，轻手绘感主要放在边框、标题底刷、气泡、箭头、道具和纸张质感上。不能把人物全身画成草稿。
- 背景是接近白色的非常浅暖白，不要明显深黄、灰色或脏旧纸。
- 深蓝/黑负责结构和主要文字，蓝色负责角色与状态，红橙只强调少数关键结论。
- 禁止 `by ian and 小黑`、签名、水印、二维码和未经要求的品牌角标。

## 交付判断

小红书合格结果还应满足：首图缩小后仍能看懂钩子；轮播每页能独立阅读且顺序清楚；文字、截图和数据证据可信；整组边框、角色、颜色和纸感统一；鲸鱼娘有灵性但不抢占信息区。

所有结果都应满足：文字能读出用户要求的核心信息；鲸鱼娘身份像参考图且有神态；画面有不对称的手绘节奏和可理解的关系；第一眼不是大型角色立绘、阀门海报、僵硬 PPT 或空标签卡。
